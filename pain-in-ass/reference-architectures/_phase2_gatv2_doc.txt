Phase 2 — GATv2 + Dynamic Financial Topology

Topology construction, graph attention, hybrid ML/GNN evaluation and path to adaptive topology

1. Purpose

Phase 2 adds relational intelligence to the Phase-1 XGBoost baseline. The goal is not to force a GNN to beat XGBoost on every metric. The goal is to determine whether relationships among underlyings, option contracts, strikes, expiries, volatility and related assets contain incremental predictive information that a tabular model does not naturally capture.

2. Key architectural correction

A GNN does not automatically receive a meaningful financial topology from a flat feature table. We must construct an initial topology from financial relationships. The GNN then learns how information should propagate across that topology. A graph-attention model can additionally learn which neighboring relationships deserve more weight.

Financial data     |Topology Builder     |Initial financial graph     |GATv2     |Learned attention / graph embeddings     |Prediction / downstream agents

4. What is the topology?

The topology is the structure defining which financial entities are connected. Nodes represent entities and edges represent meaningful financial relationships. Edge features describe relationship type or strength.

4.1 Node types

UNDERLYING — stocks/ETFs.

OPTION — individual call/put contracts.

EXPIRY — expiration-date nodes where useful.

STRIKE — strike-level nodes where useful.

MARKET_INDEX — broad market references.

SECTOR / RELATED_ASSET — sector ETFs or correlated assets.

Later: VOLATILITY_FACTOR and NEWS_EVENT.

4.2 Initial edge types

OPTION → UNDERLYING: contract belongs to underlying.

OPTION → OPTION: same expiry.

OPTION → OPTION: nearby strike.

OPTION → OPTION: same strike across call/put or expiry.

OPTION → OPTION: neighboring expiry.

UNDERLYING → RELATED_ASSET: empirical correlation.

UNDERLYING → SECTOR: sector membership.

UNDERLYING → MARKET_INDEX: market relationship.

8. Why Graph Attention?

A standard message-passing GNN aggregates neighbor information. Graph Attention learns a weight for each neighbor. GATv2 is the preferred experiment because its attention formulation is more flexible than the original GAT formulation.

Neighbor A ---- attention 0.10 --Neighbor B ---- attention 0.65 -----> Target nodeNeighbor C ---- attention 0.25 --/

Attention is learned influence weighting, not proof of causality. High attention must not be described as a causal relationship.

9. Proposed GATv2 architecture

Input graph   |Node feature projection   |GATv2 layer   |GATv2 layer   |Residual / normalization   |Node / graph embedding   |Prediction heads   +---- Direction   +---- Future RV   +---- Option Opportunity

Use multi-head attention initially.

Normalize node and edge features.

Use dropout/weight decay to control overfitting.

Use timestamp-aware train/validation/test splits.

Store attention diagnostics for selected validation examples.

10. XGBoost vs GNN experiment

Because the current GNN is not outperforming XGBoost, the next step is a controlled ablation rather than blindly increasing model complexity.

A: Features -> XGBoostB: Same features + current graph -> GNNC: Same features + meaningful financial topology -> GATv2D: XGBoost features + GATv2 embedding -> Hybrid

All experiments must use identical timestamp splits and equivalent target definitions.

11. Why GATv2 may still lose to XGBoost

The graph may add little information beyond tabular features.

Edges may be arbitrary or weakly defined.

The graph may be too small.

The target may be primarily local/tabular.

Node/edge normalization may be poor.

The GNN may overfit or oversmooth.

Graph construction may have leakage or timestamp misalignment.

Accuracy may not reflect economic value.

12. Where GNN should add value

Relational modeling is expected to be more useful for option-surface and contract-selection problems than for a simple underlying direction target.

Direction:Underlying features -> XGBoost may be strongestFuture RV:Underlying + market regime -> XGBoost may be strongestOption Opportunity:Option surface + related contracts + underlying                    -> GATv2 may add relational value

22. Scientific principle

Do not optimize the GNN merely to beat XGBoost on one accuracy number. First prove that the graph contains incremental information. If XGBoost remains better for direction while GATv2 improves option-surface decisions or risk-adjusted trading performance, a specialized hybrid system may be the correct architecture.

23. Recommended decision

Proceed with GATv2 as the next Phase-2 experiment, but improve the topology builder at the same time. The highest-priority work is meaningful, timestamp-safe financial edges—not simply making the GNN deeper. The existing Alpaca underlying and option data can generate the first topology.
